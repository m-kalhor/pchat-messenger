# نصب سپن روی سرور تازهٔ یک مشتری (1.25)

## یک بار برای همیشه (روی کامپیوتر صاحب سپن)
1. از گیت‌هاب: Actions › **Package** › آخرین اجرا › فایل `sepan-license-windows` را بگیرید و باز کنید.
2. روی `make-key.bat` دوبار کلیک کنید. فایل `sepan-license.key` (کلید **خصوصی**) کنار برنامه ساخته می‌شود و کلید **عمومی** نشان داده می‌شود.
   - کلید خصوصی را به هیچ‌کس ندهید و یک نسخهٔ پشتیبان (مثلاً روی فلش) نگه دارید. بدون آن هیچ سرور تازه‌ای فعال نمی‌شود.
3. کلید عمومی را در مخزن در `tools/license/public-key.txt` بگذارید. از این به بعد Actions › Package فایل نصب را هم می‌سازد (`sepan-server-package`).

## نصب روی سرور تازه (Ubuntu 22.04 یا 24.04، x86_64)
```
scp sepan-server-1.25.0.tar.gz root@SERVER:/root/
ssh root@SERVER
tar xzf sepan-server-1.25.0.tar.gz && bash sepan-server-1.25.0/sepan-setup.sh
```
نصب‌کننده می‌پرسد: نام برنامه، شناسهٔ لاتین مشتری (مثلاً `acme`)، آی‌پی، دامنه (اختیاری)، نام و رمز مدیر، دسترسی پنل، پیامک (آرتا پیامک یا بعداً)، ثبت‌نام آزاد، تماس گروهی، پورت‌ها.

بعد یک **کد درخواست** (`SR1.…`) نشان می‌دهد. روی کامپیوتر صاحب سپن `activate.bat` را باز کنید، کد را بچسبانید، سقف کاربر و مدت (اختیاری) را بزنید و **کد فعال‌سازی** (`SA1.…`) را در نصب‌کننده بچسبانید. تا این کد نباشد چیزی نصب نمی‌شود.

در پایان، نشانی‌ها، رمز مدیر (اگر خودکار ساخته شد) و **کد ساخت** (`SB1.…`) نشان داده و در `/root/sepan-info.txt` ذخیره می‌شوند.

## اپ اختصاصی مشتری
1. گیت‌هاب: Actions › **Customer APK** › Run workflow › کد ساخت را بچسبانید.
   - آیکون دلخواه: قبلش یک PNG مربع در `branding/<شناسه>/icon.png` بگذارید.
2. فایل `customer-<شناسه>-apk` دو APK دارد: `<شناسه>-app.apk` و `<شناسه>-admin.apk`.
3. روی سرور: `sepan-apk app <شناسه>-app.apk` و `sepan-apk admin <شناسه>-admin.apk`. کاربران اپ را از صفحهٔ دانلود سرور می‌گیرند و به‌روزرسانی‌ها هم از همان‌جا می‌آید.

## ارتقای سرور مشتری
بستهٔ تازه را مثل بالا باز کنید و `sepan-setup.sh` را دوباره اجرا کنید. پاسخ‌های قبلی (`/root/sepan-setup.conf`) و دیتابیس می‌مانند و پشتیبان گرفته می‌شود. برنامهٔ تازه کد فعال‌سازی تازه می‌خواهد.

## نکته‌ها
- بدون کد معتبر، یا اگر یک فایل برنامه دست بخورد، سرویس بالا نمی‌آید: `journalctl -u messenger -n 5` دلیلش را می‌گوید. وضعیت: `msgadmin license status`.
- سرور خود سپن (نصب از کد منبع با `server/install.sh`) به این بخش ربطی ندارد و کد فعال‌سازی نمی‌خواهد.
- هیچ نرم‌افزاری صددرصد غیرقابل‌شکستن نیست؛ این روش دور زدن را سخت و پرهزینه می‌کند.
